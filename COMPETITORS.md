# Competitor research: Windows 11 gaming optimizers (November 2026)

The question was what these tools do that measurably helps, and what Kestrel was missing. No third-party optimizer was installed or run; findings come from vendor documentation, independent tests and user reports. **Evidence quality:** *Verified* = independently measured; *Limited* = vendor claims, small or single tests, or user reports; *Unknown* = no technical detail published.

## Summary

| Application | Useful features | Unique techniques | Evidence quality | Worth implementing? |
|---|---|---|---|---|
| **Hone** (hone.gg) | Power plan, "General Windows Optimizations", per-game boosts | Windows timer resolution change | Limited: an independent review found its 30% FPS claim didn't hold; power plan and timer resolution showed no gain in that test (run in a VM, so weak for power plans) | **No** for timer resolution. Power handling is already covered better by Windows 11 power modes |
| **Wise Game Booster** (WiseCleaner) | Lists high-memory processes and suggests ending them; one-click "Optimize all"; stops services; restore afterwards | Process + service optimizer with a backup | Limited: reviews only; killed processes aren't restarted, services can't be excluded | **Partly**: showing memory per app is useful (done). Stopping services and killing processes: **no** |
| **Razer Cortex** | Booster (ends background apps/services while gaming), Booster Prime (edits a few games' own settings files, e.g. `GameUserSettings.ini`) | Per-game settings-file profiles with an FPS "prediction" | Limited: vendor and competitor blogs report small, inconsistent gains (roughly 0–4 FPS, more only on RAM-starved PCs); Razer publishes no benchmarks | **Partly**: game-aware background management is worth doing reversibly (done). ## What the research says about the common claims
- **Killing background processes / "RAM cleaning"** (Cortex, Wise): helps mainly when a PC is short of memory. Windows already manages memory. Killing apps loses their state and they aren't restarted. → Kestrel shows what uses memory and lets you choose. The reversible option is efficiency mode, and closing only happens with a normal close request.
- **Timer resolution** (Hone): since Windows 10 2004, a process's timer request no longer changes other processes' timing unless it's set globally (Microsoft documentation, via Bitsum). An independent test found no gain. → Rejected.
- **Ping reduction**: only a different route helps (WTFast-style relays, which are paid infrastructure). Local DNS/TCP/registry "network fixes" have no credible evidence. → Rejected. Kestrel keeps its honest network check (wired vs Wi-Fi, link speed).
- **Aggressive service disabling, Defender off, debloat scripts** (Wise, Talon, EXM, VTRL): breakage reports (Edge, Xbox app, GeForce overlay) and security costs, with no measured gain. → Rejected.
- **Universal presets**: every tool sells them; none publishes reproducible results. → Kestrel reports "Already set" / "Not needed" and targets real bottlenecks.

## Implemented (0.11)
1. **Efficiency mode for your background apps during Game Mode** (inspired by Cortex's and Wise's "background process management", done reversibly). It uses Windows' documented EcoQoS switch (`SetProcessInformation` + `ProcessPowerThrottling`), the basis of Task Manager's Efficiency mode, plus below-normal priority. Apps keep running; their priority and scheduling are saved first (with the process start time, so a reused process ID is never touched) and put back when Game Mode ends or after a crash. Now part of the Performance profile in place of closing apps (closing is Custom-only). **Evidence: plausible; Microsoft documents EcoQoS for background work. No independent FPS benchmark exists**, so it's described as freeing CPU time, not as an FPS gain.
2. **Memory use in the background-app picker** (inspired by Wise's high-memory process list): open apps are sorted by memory, with sizes, so you can see what's worth quieting or closing. Together with 0.10's Memory in use check, this targets the one background bottleneck that is measurable.
3. Already present and confirmed by the research: conflict detection for other optimizers (Razer Cortex, Hone, Wise, Process Lasso and others), "already optimized" detection, per-game GPU/fullscreen settings, automatic Game Mode with crash-safe restore.

Not added to conflict detection: EXM Tweaks, VTRL and HDOpti, because their process names aren't documented and guessing could mislabel other programs.

## Debloated Windows and memory integrity (researched for 0.17)
- **Debloated builds and scripts** (AtlasOS, Tiny11, ReviOS, debloat scripts): independent reviews found no meaningful average-FPS gain on modern PCs, at most slightly steadier frame times; AtlasOS's own large claims weren't reproduced (a Rainbow Six Siege benchmark showed 444 FPS on both). Undoing them means reinstalling Windows. → Rejected; Kestrel targets what runs while you play instead. Sources: [XDA](https://www.xda-developers.com/tried-kinder-windows-experience-atlasos-how-should-be/), [TechteamGB](https://techteamgb.co.uk/2024/01/12/custom-windows-os-claims-lower-latency-and-more-performance-atlas-os/), [Brutal Optimizer](https://brutaloptimizer.com/blog/are-windows-debloat-scripts-safe-tiny11-atlas), [MakeUseOf](https://www.makeuseof.com/windows-11-mod-recommend-to-every-gamer/).
- **Memory integrity (VBS/HVCI):** measured at about 4–5% in CPU-bound games, up to about 10% in some titles, with a smaller effect on GPU-bound ones. → Offered opt-in only, behind a warning, never automatic. Sources: [Tom's Hardware](https://www.tomshardware.com/news/windows-11-gaming-benchmarks-performance-vbs-hvci-security), [Tom's Hardware (RTX 4090)](https://www.tomshardware.com/news/windows-vbs-harms-performance-rtx-4090), [Digital Trends](https://digitaltrends.com/computing/are-windows-11-security-features-killing-gaming-performance).
- **Defender exclusions for game folders:** no controlled benchmark found, only anecdotes; PCWorld notes real-time scanning is normally fast. → Rejected (security cost without evidence).

## What competitors do that Kestrel didn't (researched for 0.18)
| They do | Evidence | Kestrel |
|---|---|---|
| NVIDIA driver settings (shader cache size, power management, low latency) | Shader cache size reduces stutter in some games ([PC Gamer](https://pcgamer.com/hardware/i-fixed-borderlands-4s-stuttering-issue-by-upping-my-shader-cache-size-to-100-gb-which-feels-like-something-i-shouldnt-have-to-do-in-a-well-optimised-game), [NVIDIA forum](https://forums.developer.nvidia.com/t/pre-compiled-shader-cache-cleaned-by-nvidia-driver-causing-stutter-when-launching-vulkan-apps/336196.md)); power management mostly steadier clocks | Shader cache 10 GB added (0.18); power management deferred |
| CPU/GPU bottleneck readout (PresentMon 2, NVIDIA overlay) | Intel's GPU Busy metric ([explainer](https://windowsforum.com/news/intel-presentmon-gpu-busy-explained-how-to-spot-pc-gaming-bottlenecks.452080/)) | Added to Measure (0.18) |
| Optimal in-game settings (NVIDIA app) | Real, vendor database | Linked when the graphics card is the limit |
| Process priority / affinity boosters | Windows Game Mode already prioritizes the game; affinity matters for dual-CCD X3D, which AMD handles via Game Bar | X3D requirements check (0.18) |
| Editing game config files | Breaks with patches | Not done |

Single-channel memory: small average-FPS loss on current discrete-GPU PCs, larger in 1% lows and CPU-heavy games, large with integrated graphics ([PC Gamer](https://www.pcgamer.com/hardware/memory/single-channel-dram-is-bad-news-for-pc-gaming-but-depending-on-what-cpu-you-have-its-not-actually-as-awful-as-you-might-think/), [Tom's Hardware](https://www.tomshardware.com/pc-components/ddr5/single-dimm-ddr5-gaming-works-better-than-you-probably-think-amds-3d-v-cache-chips-drop-less-than-3-percent-one-ddr5-dimm-beats-dual-channel-ddr4-ram), [Phoronix](https://www.phoronix.com/review/single-dual-memory-linux/4)).
